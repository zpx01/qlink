QLink: QwenGPUs that talk NCCL and train together

qwenGPU compiles a 4-lane SIMT GPU into the weights of Qwen3.5-2B. This fork connects several of those models the way NVLink connects GPUs. When one model's weights write a store record, the record crosses into another model's context, where that model's own layers write it into its memory. NCCL's ring and multicast collectives run on top of that link, and so does a data-parallel training loop. Four merged Qwen3.5-2B models, one per GB200, trained a small neural network this way. The host launches kernels and routes packets by their address token. It never computes, reduces or decides a value.

The idea

A store record is already a network packet

In qwenGPU, global memory is the recurrent state of a Gated DeltaNet head: each 32-bit word is one row. The host writes memory with three tokens, <|gpu_mem a|> <|gpu=lo|> <|gpu=hi|>, and the model's memory head stores them in row a. A kernel's own st.global comes out of the model in exactly that form, as a write-back record after the warp's register values.

So a store made by one model can be fed straight into another model's context. The receiving model's layers absorb it as a memory write, exactly as they absorb the host's cudaMemcpy. That gives an interconnect with no new vocabulary and no new circuit.

Apertures. Each device has a table of address ranges whose stores leave the device, like an NVLink peer mapping. When the model writes MEM(a) for an aperture address, the device sends the record to the peers and feeds MEM(127) locally, so the word goes to the sink. A multicast aperture keeps the local write too. Loads are never routed: an aperture address still reads local memory.

Record boundaries. A packet is fed only between two records, after the model has predicted the next EXEC token and before that token goes in. There the packet only writes a memory row: the record counter is past every register-commit slot, and the next record reads memory at its EXEC. A kernel that polls a flag therefore sees a peer's store on its next loop iteration. The exact compiled circuit and the bf16 model both confirm this, token for token.

Training

Four QwenGPUs train an MLP, data-parallel

The task is XOR: label points in [−1, 1]² by the sign of x₀x₁. A linear model cannot solve it. The network is a 2-8-1 ReLU MLP with 32 parameters in Q8 fixed point (1.0 = 256), trained with mean-squared error. Each of the 4 ranks holds a replica of the parameters in its 127-word memory and a quarter of the 256 training points, and draws 8 samples per step (global batch 32). A step on each QwenGPU:

H2D        the rank's minibatch (its data loader), o = 0, loss = 0
forward    mlp_forward   64 threads   o[s] += W2[k] · relu(W1[k]·x[s] + b1[k])   (atomicAdd)
backward   mlp_backward  64 threads   per-sample gradients, atomicAdd into g; the loss
comm       T1: ring AllReduce(g)      T2: ring ReduceScatter(g) + multicast shard update
update     T1: sgd  p −= round(g / 2⁶)   T2: sgd_shard on this rank's 8 parameters

Before step 0, rank 0 initializes the parameters and a collective (ring Broadcast in T1, a multicast copy in T2) gives every rank the same replica, as DDP does at construction. All arithmetic is int32, so the run has an exact numpy replay, and the QwenGPUs' parameters must equal it after every step on every rank. They do.

Protocol

qccl: NCCL's ring algorithms on one primitive kernel

Each rank gets a ring channel at the same addresses on every rank, a symmetric heap as in NVSHMEM. The channel is a FIFO of S slots of C words, plus a tail word and a head word. Because apertures route only stores, the send side sits on the same addresses as the receive side. A kernel loads what the previous rank sent, and its stores to those addresses go to the next rank.

Flow control follows NCCL's Simple protocol. The sender waits for a free slot (head), writes the chunk into the receiver's slot, fences, and posts tail. The receiver waits for tail, consumes the slot, and posts head back. Ranks never wait on the host: each one's kernels spin on flags that peers' stores write.

Collectives are sequences of this kernel with different modes, in the order NCCL's runRing uses. AllReduce is send, (N−2)× recvReduceSend, recvReduceCopySend, (N−2)× recvCopySend, recv. SendRecv is software-pipelined like NCCL's grouped calls. Issuing every send before any receive deadlocks on a 2-slot FIFO, on QwenGPUs as with NCCL, and a test checks that it does.

// kernels/qccl/prim.cu (excerpt)
if (mode & RECV) while (*rtail < rwait) {}
if ((mode & SEND) && swait > 0)
  while (*rhead < swait) {}
int r = 0, v = 0;
if (mode & RECV)  r = rslot[i];
if (mode & LOCAL) v = x[i];
if (!(mode & SPLIT)) v += r;
if (mode & COPY)  y[i] = (mode & SPLIT) ? r : v;
if (mode & SEND)  sslot[i] = v;   // -> peer
__threadfence_system(); __syncthreads();
if (i != 0) return;
if (mode & SEND) *stail = spost;  // -> next
if (mode & RECV) *shead = rpost;  // -> prev

Driver changes that made this possible

  • Persistent device memory. Pointer arguments can be fixed device addresses (DevPtr) instead of per-launch buffers, so parameters and FIFOs stay resident across launches.
  • Memory-order qualifiers. ld.volatile and acquire/release accesses lower as plain accesses, and membar/fence are no-ops. On this machine one warp runs at a time and stores leave in program order over FIFO links, so the ordering already holds.
  • Uniform loads. A load from a warp-uniform address is warp-uniform, so while (*flag < k) compiles to a plain loop instead of forcing predication of the whole kernel.
  • Late early exit. if (threadIdx.x != 0) return; after uniform loops is if-converted, so one thread can post a flag.
  • Records as a generator. The reference interpreter now yields record by record: a record's EXEC token first (control flow only), then its body, computed from memory as it stands once peers' packets have landed.
Optimizations

Multicast, and what is cheap on a QwenGPU

On a QwenGPU, a token the model writes costs a forward pass, while a token fed in (host records, peers' packets) is prefill and nearly free. So the cost of a collective is the tokens each rank must write. A ring moves every word through every rank. A multicast window (an aperture whose stores land locally and at every peer, like NVLink SHARP's multimem.st on GB200's NVLink switch) lets each word be written once. That is the model behind the NVLS-style collectives and the ZeRO-1 training step.

The saving grows with the number of ranks, since the ring's per-rank traffic is about 2(N−1)/N of the buffer while multicast writes each word once. Multicast here is pure replication by the fabric. In-network reduction (SHARP's multimem.ld_reduce) would make the fabric add numbers, which the host never does in this design, so reductions stay in the GPUs' weights.

Why verify mode proves the greedy result. If every model's argmax equals the reference token at every position it owns, given the reference prefix, then by induction over ticks the greedy system writes exactly the reference streams: each model's first deviation would have to be at a checked position. This is the same teacher-forced check upstream qwenGPU uses in merged_check. T1 checked about 410,000 owned positions per rank. Greedy runs (E3, E4, G1) show the literal autoregressive system producing identical streams.

Limits

What this machine cannot do (yet)

  • QLink carries stores only. Remote loads (P2P reads) and remote atomics would need the peer to compute a reply. Collectives therefore push data, as NCCL's Simple and LL protocols do, and an atomic into an aperture is refused.
  • Memory is 127 words per GPU. The T2 layout uses 119 of them: channel 18, parameters 32 (a multicast window), gradients 32, batch 32, flags 4, loss 1.
  • Memory also caps tensor parallelism. A ring AllReduce moves one 4-word chunk per rank per step (4 lanes), so the MNIST logits buffer must grow to 4N words, and the channel needs two FIFO slots: with one, every rank waits for its successor's free-slot flag, which is posted only at the end of that rank's own receive-and-send launch, so the ring deadlocks (a reference test caught it). At 8 ranks MNIST would need 80 + 8 + 32 + 1 + 10 = 131 of 127 words, so M2 stays at 4.
  • Ranks advance in lockstep, one record per tick. Real GPUs are asynchronous; lockstep keeps every run deterministic and replayable on the reference. The protocol itself does not depend on it: E5 runs it on real, asynchronous GPUs.
  • Greedy decoding runs about 7 tokens/s per model on GB200, where 15 ms of GPU work per token sits under about 150 ms of host overhead (6,000 kernel launches). CUDA graphs would close most of that gap; verify mode sidesteps it.
  • Speedups that keep every check: flash-linear-attention's Gated DeltaNet kernels (a 1,024-token pass drops from 442 to 179 ms; T1 stays exact at all ~410k checked positions), a ROM diff (a launch only re-sends the program rows it changes), a CPU fabric for the per-tick exchange (it never waits behind model work on the GPU), and burst exchange (several records per collective; still deterministic). Long runs also rebase a context: read the 127 words back, start fresh, write them in again.
  • One upstream test (test_cuda::test_run[SHARED]) fails with clang 18 on the pristine upstream checkout as well (clang emits PTX the driver does not lower). It is not affected by this work.
